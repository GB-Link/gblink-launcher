# GB-Link Launcher

The official web launcher for **GB-Link**, bringing the main tools and adapter checks together in one place.

Use it to:
- quickly open supported GB-Link web clients,
- check adapter firmware health/version,
- and grab firmware updates when available.

## Links

- Hosted at: [launcher.gblink.io](https://launcher.gblink.io)
- GB-Link site: [gblink.io](https://gblink.io)
- Firmware releases: [GBLink-Firmware releases](https://github.com/starlarkus/GBLink-Firmware/releases)

## What This Launcher Does

- Loads GB-Link compatible web tools/games from `data/games.json` (kept up to date)
- Detects connected GB-Link adapters through WebUSB, with a WebSerial fallback (Firefox 151+)
- Identifies known firmware families and versions
- Flashes firmware updates **directly in the browser** over WebUSB — no download or
  drag-and-drop. On firmware ≥ v2.1.2 the board reboots itself into the bootloader
  (one click); older firmware just needs a manual BOOTSEL press first
- Flashes **bundled `.uf2`** builds shipped under `assets/firmware/`. The launcher reads
  `assets/firmware/manifest.json` (generated by scanning that folder), takes the highest
  version per family as the default, and offers older builds as optional installs. The
  version comes straight from each filename (e.g. `gblink.v2.1.2.uf2` → 2.1.2) — no
  network call. GitHub release-asset binaries aren't CORS-accessible to a web page, so
  the firmware is committed here; the always-available **Download** link still works for
  manual flashing
- Customizes the adapter's **per-mode status LED colors**, saved to the adapter's flash so
  they persist across reboots (GBLink and reconfigurable v1.0.7+)
- Optionally remembers your preferred game/tool and auto-redirects on next visit

## Tech Stack

- Static HTML/CSS/JavaScript
- WebUSB API (Chromium) with a WebSerial fallback (Firefox 151+)
- No framework or build step required

## Local Development

Because this project loads JSON files with `fetch`, run it through a local HTTP server.

Example:

```bash
python3 -m http.server 8080
```

Then open:

```text
http://localhost:8080
```

## Project Structure

- `index.html` - page markup
- `style.css` - styling
- `assets/js/launcher.js` - launcher, browser info, and device health logic
- `assets/js/flash.js` - in-browser firmware flashing (WebUSB / PICOBOOT) + serial manual flow
- `assets/js/serial-transport.js` - WebSerial fallback transport (CDC framing) for Firefox
- `assets/js/picoflash/` - vendored [picoflash](https://github.com/picoflash/picoflash) PICOBOOT library (MIT)
- `assets/firmware/` - bundled firmware `.uf2` files + generated `manifest.json`
- `scripts/gen-firmware-manifest.mjs` - regenerates the firmware manifest from the folder
- `data/games.json` - launcher destinations (updated list)
- `data/firmware.json` - firmware catalog and update metadata (latest known releases)

## Releasing new firmware

When a new GBLink firmware is released, add it to the launcher:

1. Drop the release `.uf2` into `assets/firmware/`, named `<family>.v<version>.uf2`
   (e.g. `gblink.v2.1.3.uf2` — family and version are parsed from the filename).
2. Run `node scripts/gen-firmware-manifest.mjs` to regenerate
   `assets/firmware/manifest.json`, then commit both.

No JSON to hand-edit. The launcher takes the highest version as the default install and
keeps the older builds available as optional installs. To drop an old build, delete its
`.uf2` and re-run the generator.

## Browser Notes

The device panel uses the best transport the browser offers:

- **WebUSB (Chromium — Chrome, Edge, Opera, Brave): full support.** Health, update checks,
  the landing-page toggle, and **one-click in-browser flashing** (reaches the RP2040 bootrom
  via PICOBOOT, which needs WebUSB specifically).
- **WebSerial (Firefox 151+, and Chromium): fallback.** The GBLink firmware speaks its
  command protocol over its CDC-ACM serial interface, so over WebSerial the launcher still
  shows firmware **version + USB ID**, runs the **update/version check**, toggles the
  landing page, and (on firmware ≥ v2.1.2) can **reboot the adapter into update mode**. It
  cannot PICOBOOT-flash without WebUSB, so flashing is **manual**: download the selected
  `.uf2` and drag it onto the `RPI-RP2` drive. Older reconfigurable boards over WebSerial
  are limited to USB ID + manual flash (their commands are WebUSB-only).
- **Neither available** (e.g. Safari, Firefox < 151): the game/tool links still work; the
  device panel is disabled. Firmware can always be flashed manually via the `.uf2` + BOOTSEL.

## Linux permissions

On Linux the browser needs udev access to both the running adapter and the RP2040
bootrom (`2e8a:*`) used while flashing. The firmware repo's
`scripts/setup-linux-permissions.sh` installs rules covering all of these.

## Troubleshooting flashing

- **"Access denied" right after the board enters BOOTSEL** is usually transient (the OS
  hasn't released the freshly re-enumerated device yet); the launcher retries
  automatically. If it persists, unplug/replug the adapter and try again.
- The flash flow grabs the bootrom the moment it appears (the live `connect` event), so
  it does not rely on previously-remembered permissions. If Chrome's USB chooser ever
  lists several duplicate **RP2 Boot** entries, those are harmless stale grants — clear
  them via the URL-bar USB icon or `chrome://settings/content/usbDevices`.
